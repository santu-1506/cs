EXERCISE: LOG FILE ANALYSIS FOR INCIDENT DETECTION LAB

Aim: To analyze system log files and detect suspicious activities such as failed login attempts and identify suspicious IP addresses.

Objectives

  • Understand system log files.
  • Detect suspicious activities and incidents.
  • Analyze logs using Linux tools.
  • Identify attack patterns (failed logins, brute force, etc.).

Requirements & Tools

  • Kali Linux/Ubuntu VM.
  • Basic Linux command knowledge.
  • Tools: Kali Linux, journalctl, ssh, grep, awk, sort, less, cat.

Understanding Log Files

Navigate to Log Directory
cd /var/log
ls

The /var/log directory contains system and application logs such as Apache, Nginx, and login records used for security analysis.

  • dpkg.log: package activity.
  • apache2: web server logs.
  • nginx: web logs.
  • journal: system logs (IMPORTANT).
  • wtmp, btmp: login records.

Log Analysis Commands

Successful Logins (wtmp)
last

Capture: Login history. This displays successful login sessions. It helps identify legitimate and suspicious user access.

System Logs using journalctl
journalctl | less

The journalctl command provides centralized system logs including authentication, services, and system events. Capture: Logs output.

Failed SSH Attempts
journalctl | grep "Failed"
SSH Login Activity
journalctl | grep ssh

This shows failed authentication attempts, which may indicate unauthorized access attempts. It also displays SSH-related logs, including login attempts and connections.

Error Detection
journalctl | grep -i error

Highlights system errors, which may indicate abnormal behavior or system issues.

Apache Log Analysis
cd /var/log/apache2
ls
sudo less access.log

Apache logs record web requests. These logs help identify suspicious web activity such as repeated requests or attacks.

Suspicious Requests:

grep "404" /var/log/apache2/access.log

This shows failed web requests (404 errors), which may indicate scanning or probing attacks.

Package Activity
less /var/log/dpkg.log

This shows software installation and update logs, useful for detecting unauthorized changes.

Real-Time Monitoring
sudo journalctl -f

This shows real-time system log monitoring, allowing detection of incidents as they occur.

Quick Checklist

Check Command Suspicious If
Failed logins lastb Many attempts
SSH activity journalctl | grep ssh -
Login history last Odd timing
Errors journalctl | grep error -
Web logs grep 404 Many failed requests

Step-by-Step Analysis of Your Log

  • 1. System Services (NORMAL): Finished phpsessionclean.service. Finished systemd-tmpfiles-clean.service. These are routine background tasks. No issue. Regular system maintenance services were observed, indicating normal system operation.

  • 3. Your Own SUDO Activity (NORMAL): kali: COMMAND=/usr/bin/less access.log. kali: COMMAND=/usr/bin/journalctl -f. This is YOU running commands. Not suspicious. Sudo activity corresponds to legitimate administrative actions performed by the user.

These lines are: Repeated MANY times, Coming from VirtualBox (VBoxDRM / DnD). Is This Suspicious? Technically: NOT an attack. But abnormal repetitive behavior. Lab Exp 3: NETWORK FORENSICS USING WIRESHARK

Aim: To capture and analyse network packets using Wireshark and understand network forensics techniques.

Objectives

  • To learn packet capturing using Wireshark.
  • To analyze different network protocols.
  • To apply filters for identifying specific traffic.
  • To understand how network forensics helps in detecting suspicious activities.

Introduction

Network forensics is a branch of digital forensics that deals with monitoring, capturing, and analyzing network traffic to detect security breaches and malicious activities. Wireshark is a widely used open-source tool that helps in capturing real-time packets and analyzing them in detail.

Tools Required:

  1. Kali Linux
  2. Wireshark

Procedure

Step 1: Open kali linux terminal

Type the following command:

wireshark &

Wireshark is launched to begin packet analysis. It provides a graphical interface to monitor all incoming and outgoing packets in a network. It supports multiple protocols and helps in detailed inspection.

Step 2: Select interface

Select eth0.

Step 3: Protocol Analysis (TCP/UDP/HTTP)

Wireshark supports deep inspection of protocols such as TCP, UDP, and HTTP. TCP ensures reliable communication, while UDP is faster but connectionless. HTTP packets help analyze web traffic and identify requests and responses.

Apply filter as tcp...now you can able to see the only tcp packets. You can also try with UDP, HTTP.

Step 4: Applying Filters

Filters are used to narrow down specific packets. For example: ip.addr == 192.168.0.161 → filters packets of a specific IP. This simplifies analysis by focusing only on relevant data.

Step 5: Filter for particular Source address

Use ip.src==<IP_Address> like:

ip.src==192.168.0.161
Step 6: Following TCP Stream

The "Follow TCP Stream" feature reconstructs communication between two endpoints. It helps in analyzing complete conversations, such as HTTP requests and responses, making it useful in forensic investigations.

Right click on any TCP packet → Follow → TCP Stream

Observation on above tcp stream:

  • Complete conversation between two devices over TCP.
  • Red text → Data sent from one device.
  • Blue text → Data sent from the other device.
  • It reconstructs the entire communication stream.
  • Mixed Content (Binary + Text). You see: Random characters → binary data, Some readable text → application data. This means: It is not plain HTTP. Likely: Encrypted traffic (HTTPS) Or application-level data.
  • TCP Flags Visible. You can see: [SYN], [ACK], [PSH], [FIN]. Meaning: SYN → Connection start, ACK → Acknowledgement, PSH → Data transfer, FIN → Connection close. So this stream shows: Full TCP session lifecycle.
Step 7: Identifying Suspicious Traffic

Open kali linux terminal. Type nmap -sS <target_IP>.

nmap -sS 192.168.0.156

(use your windows ip).

Open wireshark. Use this filter:

tcp.flags.syn == 1 && tcp.flags.ack == 0

Now you will observe:

  • Multiple SYN packets.
  • Different ports.
  • Incomplete connections.
  • Source address is Kali linux and Destination Address is Windows.

This is port scanning behavior (suspicious). Any way our system firewall stops this.

Step 8: Capture File Properties

In wireshark, Go to Statistics → Capture File Properties.

Step 9: Resolved Addresses

It provides a quick overview of network traffic and helps detect suspicious activities without analyzing each packet individually.

In wireshark, Go To Statistics → Resolved Address. Resolve Address in Wireshark converts numerical network addresses (like IP or MAC) into human-readable names such as domain names or device names.

Step 10: Protocol Hierarchy Statistics

Go to Statistics → Protocol Hierarchy Statistics. Protocol Hierarchy Statistics shows the breakdown of all network protocols in the captured traffic in a hierarchical (layer-wise) format along with their percentage and packet count.

Step 11: Conversations

Go to Statistics → Conversations. Conversations in Wireshark shows communication between two endpoints (devices), including source and destination addresses, number of packets, and data transferred.

Step 12: Packet Length

Go to Statistics → Packet Length. Packet Length refers to the size of a network packet measured in bytes, as captured by Wireshark.

Step 13: End Points

Go to Statistics → End Points. Endpoints in Wireshark represent individual network devices (hosts) involved in communication. It shows each device separately along with the number of packets sent/received and data usage.

Step 14: I/O Graphs

Go to Statistics → I/O Graphs. I/O Graphs (Input/Output Graphs) in Wireshark are used to display network traffic over time in the form of a graph, showing the number of packets or bytes captured per second.

Result

Network packets were successfully captured and analyzed using Wireshark. Different protocols and communication patterns were observed and studied.

Conclusion

Wireshark is an effective tool for network forensics. It helps in capturing and analyzing network traffic, identifying suspicious activities, and understanding communication between systems. It plays a vital role in cybersecurity and incident investigation.

  • What is a protocol analyzer?
  • What is a filter in Wireshark?
